## 4. Authoring rules (the gates enforce these; don't fight them)

1. **Root-absolute URLs only** (`/surgeons/`, `/assets/…`, `https://oklahomasurgicalarts.com/…`). Never `x.html`, never `assets/…`. Single- and double-quoted attributes are both checked (C1).
2. **One `@graph` per page.** Organization `https://<host>/#organization`, `#website`, `<canonical>#webpage`; people at `/surgeons/#slug`; fellowship `#program`; procedures `/<slug>/#procedure` (Spanish pages share the English procedure entity). Never put the practice's Wikidata id on a person. Schema is regenerated by `_pipeline/fix_audit_2026-08-21.py` (S1) — edit the Person tables in that script, not the pages.
3. **Identity facts come from `backend/seed/sitedata.json`** (phone `+19183927900`, credentials, NPIs). If a page and the seed disagree, fix the seed, then regenerate.
4. **Clinical content renders only through the sign-off law.** Anything a patient might act on (fasting windows, drain thresholds, warning signs, guides, aftercare timelines, a publication record) lives in `<template data-clinical-module="id">` until a named surgeon signs it in the registry. `_pipeline/apply_signoffs.py` flips it; `_pipeline/render_guides.py` stamps and renders guides. **Never move content out of a template by hand.** Never write "Approved"/"Reviewed" text yourself.
5. **Claims carry a source and an as-of.** No "projected", no counts without a dated source ("1 of 16" is accurate today only with the ABCS register and a date — owner decision Q10). Board certification is always followed by the board's name and year.
6. **Regulated-drug copy** (GLP-1, peptides, hormones, pellets, Rx products) names the molecule and its FDA/compounded status or says nothing. `check_medical_claims` (astro-site/cli.py) is the reference gate; its estate port is W34 (pending).
7. **Owner laws** live in `_pipeline/gate_owner_laws.py` (L1–L17). Notably L6: the phrase "published/publishable cases" is retired; L10: no "In clinical review" cards on `resources.html`. If a law conflicts with a gate, the owner resolves it — you do not pick a side by editing the gate.
8. **The never-ship set**: `backend/`, `_pipeline/`, `*.py`, `*.pyc`, `*.sql`, `*.md`, `MANIFEST.sha256`, `_integration-snippet*`, `.writer.lock`, " 2" names. These are excluded by the ship script and asserted by gate C10.
9. **Manifest last.** `python3 _pipeline/make_manifest.py` is the final step after any edit; the ship refuses on drift.

## 6. The ship path (the only one)

```bash
cd ~/dev/practice-stack-enterprise
ops/aws/publish_router.sh both                                   # only from committed sources; runs 14 vectors on the DEVELOPMENT stage
WRITER_ID=<your-id> SHIP_ACK=yes ops/aws/ship_estate.sh "$HOME/Desktop/TULSA_SURGICAL_ARTS copy/THE_REAL_SITE_2026-08-19" <YYYY-MM-DD-rcN>
```
`ship_estate.sh`: writer lock → all gates → manifest → LIVE router == committed source → **new** rc prefix only (releases are immutable; the bucket policy enforces it) → never-ship assertion → cache tiers with explicit content-types → change list vs the serving rc → upload → repoint by origin Id `s3-releases` → wait → invalidate `/*` → wait → edge/local parity on every sitemap URL. `STAGE_ONLY=1` / `REPOINT_ONLY=1` split the upload from the repoint. ## 7. The router

- Source of truth: `ops/aws/cf-function-rewrite.js` (TSA) and `cf-function-estate-osa.js` (OSA), < 10,000 bytes each, unit-tested in `ops-tasks/tests/test_aws_scaffolding.py`, vectors in `ops/aws/router-vectors/`.
- Behaviour: `/x/`→`x.html`; `/x`,`/x.html`→301 `/x/`; `www.`→apex; legacy map entries 301 to the **equivalent page** (never a gallery fragment when a page exists); `/osa/*`→301 to the OSA host; `/backend/*`, `/_pipeline/*`, the gate script, the manifest and `/404` return 404.
- A new page whose slug is in the legacy map is shadowed until the map row is removed — gate C2 catches it; fix the map, commit, publish.

## 8. The owner's console and decisions

- **Hosted ATLAS Console** (the surgeons' interface — their laptops and phones, their own login): `ops/console/` in the stack repo → Lambda + HTTP API + S3 store + Cognito (roles `owner`, `signer`, `viewer`) in `atlas-authority-prod`; deployed by `ops/console/deploy.sh` (`add-user`, `custom-domain console.atlas-authority.com`). The console holds a **workspace** (every registry module with the exact HTML a signature covers, the decision queue) and the surgeons' **edits, signatures and answers**. It never touches the website: `_pipeline/console_sync.py both` on the operator Mac (launch agent `com.atlasauthority.console-sync`, every 2 min) **pushes** the tree's truth and **pulls** signatures/edits/answers into the registries and templates, runs `apply_signoffs.py` / `render_guides.py` / `make_manifest.py`, and commits. Edits are sanitized server-side (tag allow-list; no scripts, styles, handlers or non-https hrefs) and a signature binds the sha256 of exactly the bytes previewed; a changed preview refuses the signature. Publishing is still §6.
- **Local review console** (operator only): `http://localhost:8766/` (`_pipeline/review_console.py`, launch agent `com.atlasauthority.review-console`) — same queues, same audit trail (`_pipeline/signoff_audit.jsonl`), gates on demand.
- **Rule for agents:** never write `status: SIGNED`, `signedBy`, `reviewed_by`, or a `data-signed` attribute yourself. Signatures come from a named human through one of the two consoles; everything else is a bypass and the gates treat it as one.
- **Terraform/Fargate** are not prerequisites for the console (it is serverless); they are the platform's Phase 2 (evict the management account, apply the authored plan) and the gateway's Phase C1. Write new infrastructure as importable modules under `ops/aws/terraform/modules/` when it stabilises.
- **Decision queue:** `WORK_PLAN_2026-08-22.md` §8 (Q1–Q19). An unanswered question means the content stays as it is. Read `owner_decisions.json` before proposing copy changes in those areas.
- **Reference documents** (in `~/Desktop/AWS_KNOWLEDGE/` and the tree root): `WORK_PLAN_2026-08-22.md` (what/how/who/gate), `AUDIT_ADJUDICATION_2026-08-21.md`, `ENGINE_DEFECT_CATALOGUE_2026-08-21.md`, `ATLAS_DIRECTIVE_2026-08-21.md` (the platform roadmap and phase gates), `AWS_ESTATE.md`, `ops/aws/ROLLBACK.md`.
